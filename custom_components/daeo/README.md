# DAEO Home Assistant integration

This custom integration connects Home Assistant to a running Day Ahead Energy
Optimizer engine (the add-on or a standalone container). It creates native entities,
services, an EV charging calendar, and diagnostics.

> **Status:** monitoring and battery control. The engine uses the CBC solver for the
> supported device set; household load is still synthetic. Battery control is opt-in,
> verified, and falls back to idle.

## Installation

1. Run the DAEO engine (add-on or `docker compose up`).
2. Get the engine API token:
   - Standalone: `docker compose exec daeo cat /data/api_token`
   - Home Assistant OS add-on: `docker exec addon_local_daeo cat /data/api_token`
     (check the container name with `docker ps`).
3. Add this repository to HACS as a custom repository (category: Integration), or copy
   `custom_components/daeo` to your Home Assistant `config/custom_components/` folder.
4. Restart Home Assistant.
5. Add the **Day Ahead Energy Optimizer** integration and enter:
   - Engine URL: `http://homeassistant.local:8099` (or the add-on host)
   - API token: the value from step 2. The add-on prints it in the log and stores it
     in `/data/api_token`.

## Battery control

Battery control is **off by default**. Turn on `switch.daeo_battery_control` (or call
`daeo.arm_control`) to arm it.

Requirements in the engine configuration for the first battery:

- `setpoint_entity`: a `number` or `input_number` that accepts an AC power setpoint
  in W. Signed by default (+ charge / − discharge).
- `mode_entity` (optional): a `select` or `input_select` with
  `mode_charge`, `mode_discharge`, and optionally `mode_idle` values.
- `soc_entity` (optional but recommended): the battery SOC sensor. If set, the
  controller refuses to charge at the top or discharge at the bottom of the configured
  SOC range, and falls back if the SOC is unavailable.
- `setpoint_is_unsigned` + `mode_entity`: use a positive magnitude and a separate
  direction select (official Anker Solix integration: Power Control + Grid Flow).
- `control_mode_entity` + `control_mode_value` + `control_mode_fallback`: set the
  vendor's operating mode to third-party control on arm and restore self-consumption
  on disarm.
- `control_switch_entity`: optional master switch (e.g. Anker X1 Modbus Control) that
  is turned on when armed and off on disarm/fallback.
- `invert_setpoint`: for vendors using + discharge / − charge.
- `setpoint_feedback_entity`: verify the written setpoint when the setpoint entity
  itself reports actual power.

Anker-specific mapping: see [`docs/anker-modbus.md`](../../docs/anker-modbus.md).

The controller:

- applies only the current plan interval,
- refreshes the plan when it is older than the interval (throttled),
- verifies the entity state after every write and retries once,
- falls back to power 0 and the idle mode on stale/mismatched plans or write failure,
- disarms itself after a write failure,
- records an audit trail and fires `daeo_control_applied`, `daeo_control_failed`, and
  `daeo_control_fallback` events.

The Enphase IQ Battery does not expose a generic signed power setpoint in all
setups. If your Enphase system only exposes a mode/reserve selector, this generic
controller cannot drive it yet; a device-specific driver is needed.

## Control services

- `daeo.arm_control`
- `daeo.disarm_control`
- `daeo.apply_now`

## Services

- `daeo.optimize` — recompute the plan.
- `daeo.set_strategy` — set `minimize_cost` or `minimize_import`.
- `daeo.export_plan` — return the latest plan as a service response.

## Limitations

- The engine is the source of truth. The integration polls it every five minutes.
- Control covers the first battery's power/mode entities; boiler, EV, and machine
  control is not implemented.
- The engine uses CBC for the supported device set; household load is synthetic.
- Enphase-specific battery control needs a driver with a signed power setpoint.
- The integration has not been validated against a live Home Assistant test harness in
  CI yet; it is a scaffold for the M3 milestone.

See `docs/rebuild-proposal.md` for the full architecture and roadmap.
